Section 01

What Are We Predicting?

A plain-English look at the competition, the data, and the challenge.

Imagine you're flying a drone over an Australian pasture and taking a photo. From only that photo, you need to answer five distinct questions a farmer would ask: How much living green grass is here? How much dead litter? How much clover specifically? What's the total "green energy" available for grazing (GDM)? And what's the total weight of everything combined? — all without ever stepping on the ground.

This is the CSIRO Image2Biomass challenge. Given aerial images of Australian pastures, predict 5 continuous biomass targets, each weighted differently in the evaluation because they matter differently to real-world farmers.

With only 357 training images across diverse sites and seasons, the dataset was intentionally tiny. This mercilessly punished overfitting — standard approaches like heavy augmentation or fine-tuned ensembles all fell apart on the private leaderboard.

Evaluation Metric

A single globally weighted R² is computed across all (image, target) pairs together — not averaged per-target. Each prediction row is weighted by its target's weight. This means nailing Dry_Total_g (50% weight) drives most of the score, while the four other targets contribute the remaining 50%.

Section 03

Model Architecture

Visual Prompt Tuning meets DETR-style task tokens — inside a frozen DINOv3 transformer.

Imagine giving a pre-trained AI four coloured sticky notes — one for Green, one for Clover, one for GDM, one for Total — plus sixteen guide cards. They all travel through the AI together. Dead matter is then derived from the others rather than predicted directly, since it's the noisiest target. When the tokens come out the other side, each has absorbed exactly the knowledge relevant to its target.

1
Image → Patches

The input image is sliced into a grid of 16×16 pixel patches. Each patch is linearly projected into a 768-dimensional embedding vector.

2
Append 4 Task Tokens

4 learnable task tokens are appended — one each for Dry_Green_g, Dry_Clover_g, GDM_g, and Dry_Total_g. Dry_Dead_g is derived separately (it's the noisiest target). Each token is initialized from real training data (→ Section 04).

3
Append 16 Prompt Tokens

16 learnable prompt tokens join the sequence. These are the only truly trainable parameters in the entire model — the backbone is 100% frozen. They don't carry predictions; they steer the frozen backbone's attention toward what matters for biomass regression.

4
DINOv3 Forward Pass (Frozen)

The frozen transformer processes all tokens jointly via self-attention — patches, task tokens, and prompt tokens all attend to each other across every layer. Zero backbone parameters are updated.

5
Feature Extraction — Prompt Tokens Discarded

From the backbone output, only patch outputs and task token outputs are kept. The 16 prompt token outputs are discarded — they've done their job by shaping attention during the forward pass. Two statistics are then computed from all patch outputs: GAP (Global Average Pool — the mean patch vector, capturing the average scene description) and STD (Global Std Pool — the standard deviation, capturing how diverse or varied the patch features are).

6
Per-Target Heads + Dead Derivation

Each of the 4 MLP heads receives an input formed by concatenating three things: [its own task token output] + [GAP] + [STD]. Crucially, no head sees another target's task token — keeping the predictions independent. Dry_Dead_g is then derived from the other outputs rather than predicted directly.

💡 Wait — why bother with prompt tokens if they're discarded at the output?

Great question. The backbone has zero trainable parameters — every weight is frozen. So how does the model learn anything at all? Entirely through the prompt tokens. During the forward pass, the frozen transformer's self-attention layers see the prompt tokens as part of the input sequence. They influence which patches the attention heads focus on, and how the task tokens mix information from the image. Think of it like a tour guide walking an expert through a museum: the guide doesn't become the output, but without the guide the expert stares at the wrong exhibits. The prompt tokens are the guide — they're the entire adaptation mechanism, and they're only 16 × 768 = ~12k learnable numbers vs. millions of frozen backbone weights. That's why this avoids overfitting on just 357 images.

Section 04

Self Prompt Tuning

Smarter token initialization — seeding each token with domain knowledge before training even begins.

Instead of starting your sticky notes blank (random), you look at the 10 training images with the highest value for each target. You average their AI "fingerprints" (CLS embeddings) and use that as the starting point for that target's token. It's like handing a student the most extreme, clearest examples before the exam, rather than starting from zero.

🔍
Top-10 Selection per Target

For each of the 4 targets, select the 10 training samples with the highest value of that target. These represent the clearest, most extreme signal for that biomass type.

🧠
Extract CLS Embeddings

Pass each selected image through DINOv3 and extract the [CLS] token — the model's global summary vector of the image. This is a 768-dimensional fingerprint.

📐
Average → Initialize Task Token

Compute the mean of the 10 CLS embeddings. Use this as the initial value of that target's task token. Done for all 4 task tokens (Dry_Green_g, Dry_Clover_g, GDM_g, Dry_Total_g) and for all 16 prompt tokens (split into 4 groups of 4, one group per target).

🔄
Gram–Schmidt Orthogonalization

Because all tokens now start from correlated representations, they'd immediately collapse. We apply Gram–Schmidt to make every token mutually perpendicular — preserving informed starting points while ensuring diversity.

Gram–Schmidt: Before & After

Before: all task tokens point in nearly the same direction. After Gram–Schmidt: each token is forced perpendicular, ensuring diverse representations from the very first step.

Section 05

Orthogonality Loss

Preventing token collapse — making sure each token stays distinct throughout training.

Imagine 4 people in a meeting who all start saying the exact same thing. Pointless. The orthogonality loss is a rule that says: "You're only useful if you contribute something different from everyone else." It keeps each task token focused on a unique aspect of the input — just like multi-head attention keeps each head looking in a different direction.

With Orthogonality Loss DIVERSE

Cosine Similarity Matrix

The math behind it: For tokens t₁, t₂, …, tₙ, the orthogonality loss penalizes non-zero off-diagonal entries in the Gram matrix G = TᵀT. Specifically: L_orth = ‖G − I‖²_F, where I is the identity matrix. This forces each token pair to be uncorrelated, maintaining the full representational capacity of the multi-token design.

Section 06

Two-Stream Architecture Evolution

Three iterations. One breakthrough. Why mean aggregation outperformed both concat and sum.

Imagine two people each see half of a jigsaw puzzle separately. Strategy A: combine all their pieces before guessing — messy. Strategy B: each person guesses from their half and you sum — no one knows who was wrong. Strategy C: each person guesses the full picture from just their half, then you average — independent thinkers who agree are far more trustworthy.

Strategy A: Concat then Predict

Each image is split into two halves. Both halves are independently embedded, then the embeddings are concatenated into one large feature vector, which is fed to a single prediction head.

❌ Too complex — sensitive to noise, high dimensionality

The concatenated representation doubles the head's input size, making it harder to learn. Small perturbations in either half propagate amplified to the output.

Strategy B: Sum Predictions

Each half independently produces a prediction through its own head. The two predictions are summed to give the final output. Cleaner than concat, but a fundamental issue remains.

⚠️ No supervision signal — which half caused the error?

Because the loss is computed on the sum, neither stream knows how much it individually contributed to the error. This limits what the model can learn. Pseudo-labels didn't help here either.

Strategy C: Mean Aggregation ✓

Each half predicts the total biomass of the full region using only half the visual information. The mean of both predictions is compared against the ground truth. A crucial information bottleneck emerges.

✅ Forces independent robustness per stream

Each head is now forced to be correct on its own. The gradient from the mean loss flows equally to both heads. This dramatically reduced the train-val gap and improved leaderboard performance.

Section 07

The Information Bottleneck

What happens when you force a model to predict the whole from a tiny piece — again and again?

Could you recognize a forest by looking through a keyhole? If you practise enough, you'd stop memorizing the whole scene and start learning what truly matters: the texture of the leaves, the density of the undergrowth, the quality of the light. That's exactly what random cropping forces the model to do.

Training images are 1000×2000 pixels. Random crops of 448×448 are taken — covering roughly ~10% of the total image area. The model must predict the biomass of the entire region from this tiny window.

Despite this drastic restriction, the model achieved LB scores above 0.6 — proving it was learning global textural cues, not memorizing local patterns.

Section 08

Full Dataset Training Without Validation

Once you know how long to train, why hold back any data? The Chris Deotte method applied to vision.

Cross-validation told us the optimal training duration. So instead of wasting 20% of our only 357 images for monitoring, we trained on all 357 images and simply stopped at the same point. More data, same stopping criterion — consistently better leaderboard results.

The approach is most famously applied in tabular ML (XGBoost, etc.) by Chris Deotte, but the principle transfers: estimate optimal training duration from CV, then retrain on the full dataset to that duration.

Section 11

Key Takeaways

Five lessons from this competition that apply broadly across vision and ML challenges.

🏛️
Generalization > Memorization
On small datasets, a model's ability to generalize to unseen data matters far more than squeezing CV performance. Self-supervised backbones like DINOv3 provide representations that transfer without fine-tuning.
🔑
Information Bottleneck as Regularizer
Forcing the model to predict the whole from a tiny part (10% of the image) acts as a powerful implicit regularizer. The model is compelled to learn structural and textural priors, not memorize specific pixel patterns.
🎯
Prompt & Task Tokens for Dense Regression
Visual Prompt Tuning is an underused technique for regression tasks. Learnable task tokens routed to per-target heads, combined with orthogonality loss, provides a lightweight yet powerful way to adapt frozen backbones.
📈
Full-Dataset Training with CV Signal
Once CV tells you how long to train, using a validation split is wasteful — especially on tiny datasets. Retrain on everything until you hit the mean CV training loss. Consistently outperforms ensembling the CV models.
🔀
Token Diversity is Learnable
Without explicit supervision, multiple learnable tokens collapse into identical representations. Orthogonality loss is a simple, effective solution that maintains the multi-token design's full representational capacity throughout training.
